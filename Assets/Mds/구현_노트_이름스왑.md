# 10. 맵 제작 방식 (확정)

## 10.1 방 = 독립 세트 (물리적 연결 안 함)
- 플레이어는 관리실 밖으로 안 나감 → 방들을 물리적으로 연결할 필요 없음.
- 각 방 = CCTV용 독립 세트. 서로 떨어뜨려 배치(오히려 작업/관리 편함).
- 귀신 이동 = 노드 순간이동(MoveToNode). 걸어가는 경로 불필요.
- 방 안 카메라(CAM01·02·05)는 방만, 복도 카메라(CAM03·04·06)는 복도만 봄 → 한 카메라가 방+복도 동시에 볼 일 없음.

## 10.2 복도 입구 처리 = "어둠" (방법 C 확정)
- **컨셉:** 불탄 독서실 → 문짝 타서 없음, 문틀 반쯤 부서짐, 입구 뻥 뚫림.
- 복도 CCTV로 보면 입구 너머가 보여야 자연스러움. 근데 실제 방을 붙이지 않음.
- **처리:** 입구 너머 = 얕게 판 검은 공간 + 그을음 + 잔해 실루엣 1~2개. 어둠에 잠겨 안 보임.
- "타서 뚫렸는데 안은 시커메서 안 보이는 입구" = 오싹함 + 독립성 유지.
- 실제 그 방(예: 공부방1)은 딴 데 따로, 해당 방 카메라(CAM01)가 담당.

## 10.3 텍스처/에셋 끼우는 법 (Phase 8, 걱정 해소용)
- **구조와 표면은 분리.** 지금 회색 박스로 구조(벽 위치·크기·물건 배치) 확정 → 나중에 표면만 교체.
- **텍스처:** 회색 큐브에 Material만 갈아끼움(모니터 Unlit처럼). 큐브 다시 안 만듦, 겉면만 바뀜.
- **에셋:** "책상 큐브" = placeholder → 나중에 진짜 책상 모델을 그 자리에 놓고 큐브 삭제.
- **조명+저해상도 필터**(Phase 8)로 최종 호러 룩.
- 무료 텍스처: ambientCG, Poly Haven, textures.com. 에셋: 스토어 office/school 팩.

# 11. 연호 종 메커니즘 (확정 — §7 열린 질문 해결)

> ⚠️ **현행 규칙은 §15.5.** 웹 세션에서 "인접(뒤쪽) 방" → "**연호가 지금 있는 방**"으로 바뀌었고 이 문서엔 반영이 안 됐었음(2026-11-24 확인). 아래 §11.1·§11.3의 인접 방 규칙은 지금은 **창문앞 상태에만** 남아 있음(세로복도에 쳐야 먹힘). §11.2의 "광역 폐기 이유"는 여전히 유효.

## 11.1 결정: 인접 방 유인 (원작 FNAF3식)
> ⚠️ **2026-11-26:** 진짜 원작식 유인(옆방 어디든, 끌어올 수도 있음)으로 구현 — §15.24가 현행.
- **종 = 연호를 뒤로 밀어내는 방어 도구** (조종 도구 아님 — 연호 무서움 유지).
- **인접 방에만 유인:** 연호 현재 위치와 직접 연결된 방에 종을 울려야 후퇴.
  - 엉뚱한(먼) 방에 울리면 → **헛방** (효과 없음, 종 횟수만 낭비).
- **효과:** 종 난 방(연호 뒤쪽)으로 유인 = 창문에서 멀어짐 = 후퇴.
- **핵심:** CCTV로 연호 위치를 정확히 파악해야 어느 방에 종 울릴지 앎 → 위치 추적 강제 → 긴장/공포.

## 11.2 왜 이 방식 (광역 밀어내기 폐기 이유)
- 광역이면 CCTV 안 봐도 종 연타로 대응 → 연호가 안 무서움.
- 인접 한정이면 연호를 계속 쫓아야 함 → 놓치면 헛방 → 메인 빌런의 압박 유지.
- 연호 정체성(항상 창문 수렴하는 정공법 빌런) 보호: 종으로 자유 조종 불가.

## 11.3 아직 구현 시 정할 것
- **유인 방식:** 루트 밖으로 끌기 X → **정해진 루트(노드) 상에서 뒤로 후퇴**. (연호는 노드 기반 이동)
  - 종 난 방이 연호 뒤쪽 노드면 유인 성공, 앞쪽/무관하면 헛방.
- **"인접" 판정:** 맵 인접관계를 종 로직에 반영 (연호 현재 노드의 이전 노드 = 유인 가능 대상).
- **거리별 후퇴량 / 무시 확률 1/7 / 창문 앞 무시 없음** 등은 기존 GDD 유지.
- 루트 다양화(L1~L3 + 추가)는 종과 별개로 계속 확장 가능 — 연호 다이나믹함은 행동 엔진(흉포 토글)에서 주로 나옴.

## 12.1 카메라 에러 = 과사용 처벌 (FNAF3 비디오 에러 이식)
- **원작 확인:** FNAF3 카메라 에러 = CCTV를 너무 많이/오래 쓰면 발생. 화면이 스태틱으로 완전히 덮여 아무것도 안 보임(흐려짐이 아니라 완전 먹통). 귀신 위치 파악 불가. 단 **오디오(종)는 여전히 사용 가능**. 리셋 패널에서 camera system 리부팅(~5초).
- **우리 적용:**
  - **원인:** CCTV 과사용(너무 오래/자주 켜둠). "계속 감시 vs 과열 고장" 자원관리 긴장.
  - **효과:** CCTV 완전 먹통(스태틱). 귀신 위치 못 봄. **종은 계속 사용 가능**(원작대로).

  - **현우 무관:** 현우는 환풍구 집중, 카메라 에러는 순수 과사용 처벌(역할 분리).

  - (§8.1 에러 패널 UI가 이 3종 + reboot all + exit 항목)

## 12.2 현우 2스택 후폭풍 변경

# 13. 준영 재설계 (확정 — 창문 왼쪽 방해꾼)

> ⚠️ **2026-11-24~25 변경(§15.13):** "창문 가리기" 기능 **뺌** → 위치는 **관리실 구석**(기획서 원안·원작 팬텀 폭시와 같음). 출현은 "CCTV 올릴 때마다 주사위"로 확정. 아래 §13.1의 창문 밖 배치·가림 설명은 옛 내용.

## 13.1 결정: 창문 밖 왼쪽 실루엣 (원작 팬텀 포시 각도 반영)
- **출현:** 창문 **왼쪽 밖**에 실루엣으로 서 있음(창문 안쪽 아님, 바깥). 맵이 좁아 창문 밖 배치 가능.
- **방해 효과 (핵심):** 준영이 서 있으면 **현승/연호 창문 실루엣을 가림** → 창문 감시 방해.
  - 준영 하나가 현승 응시 대응 + 연호 종 대응을 동시에 방해 → 교란형의 이상적 형태.
  - "준영부터 치울까 vs 창문 지킬까" 딜레마.
- **대응:** 유예 시간 안에 **CCTV 켜면 사라짐**(안전). CCTV 켜기 = 정답 행동.
- **무시 시:** 대응 안 하고 딴 구역으로 시야 돌리면 → **armed** → 가운데(정면) 복귀 시(화면 전환) → **점프스케어**.
- **결과:** 교란형(즉사 아님) → **환기 오류 ON**(김욱과 동일 결과).

## 13.2 armed 판정 (CCTV 켜기와 충돌 방지)
- 준영 출현 = 아직 armed 아님, **유예 시간** 있음.
- 유예 안에 CCTV 켜기 → armed 되기 전에 사라짐(안전).
- 유예 안에 무시하고 딴 구역 돌림 → armed → 정면 복귀 시 점프.
- 즉 "CCTV 켜기"는 안전, "무시하고 구역 전환"만 armed. → ScreenTransitionDetector 공통 원리 사용하되 준영은 CCTV-down을 안전행동으로 예외 처리.

## 13.3 김욱과 대칭 유지
- 김욱: CCTV **안**에 나타남 → 카메라에서 **벗어나야** 안전.
- 준영: 창문 밖(CCTV 밖) → **CCTV를 켜야** 안전.
- 정반대 대응. 출현 확률: 3일 낮음(<1/50) → 5일 1/10. AI 없음(확률 출현), 하루 1회=점프 1회.

# 14. 현승 점프스케어 트리거 변경 (C안 — 원작 팬텀 프레디식 자동 발동)

## 14.1 변경 결정
- **기존(§0.5 통일):** armed → 화면 전환(CCTV/패널 올림·내림) 순간 STRIKE1.
- **변경(C안):** armed → **자동 타이머**(2~3초) → STRIKE1 자동 발동. 화면 전환 무관.
- **이유:** 원작 팬텀 프레디에 충실("숨었다가 몇 초 후 자동 점프"). "CCTV 켜자마자 즉발"의 어색함 제거. armed인데 CCTV 안 켜면 안 터지는 도망 구멍도 없음(자동이라).

## 14.2 연출 순서 (우리 현승 = 숨는 단계 없음)
- 우리 현승은 창문 워크패스(6초 가로질러 지나감)가 곧 응시 기회. 원작 프레디의 "바닥으로 숨는" 단계는 **우리엔 없음**.
1. 워크패스(창문 앞 6초 지나감) = 응시 기회.
2. 다 지나갈 때까지 응시 실패 → armed.
3. armed 후 **짧은 뜸(1~2초 정적, 긴장감용)** → 자동 발동. (숨는 연출 아님, 그냥 터지기 직전 정적)
4. 플레이어가 CCTV/패널 보고 있었으면 → **강제 정면 복귀**(jumpscare.Play() 내 ForceCancel 이미 구현됨).
5. 점프스케어(얼굴 확) → 오디오 고장.
- 짧은 뜸 없이 즉시 발동도 가능(프로토타입에서 택). 핵심은 화면 전환 대기 없이 자동.

## 14.3 구현 방향
- armed 되면 hideTimer 시작 → 끝나면 Strike1() 자동 호출.
- 현승은 ScreenTransitionDetector 구독 **제거**(자동 타이머로 대체).
- jumpscare.Play()의 ForceCancel(화면 강제 복귀)은 그대로 재사용 → 4번 연출.

## 15.13 준영 (팬텀 폭시) — 구현
- **창문 가리기 뺌** (유저 결정). 이유: ① 딜레마("준영 치울까 vs 창문 지킬까")는 규칙으로 이미 생김 — 피하려면 CCTV를 다시 올려야 해서 현승 응시 불가 + 그 자체가 화면 전환이라 창문앞 연호는 빼꼼 ② 현승 응시는 GazeBox 판정이라 가려도 응시가 그대로 돼서 눈속임이 됨 ③ 위치가 자유로워짐. → **관리실 구석**(정면 시야 가장자리).
- **원작 조사(팬 가이드):** 팬텀 폭시는 경로 없이 사무실 안에 갑자기 나타남, 예측 불가, 3일차~. 모니터 올려두면 피하고, 내려가 있으면 쳐다보기 전에 올려야 피함. 실패 시 환기 오류. ("모니터 자주 쓰면 잘 나온다"는 설은 미확인)
- **출현:** **CCTV를 올릴 때마다 주사위.** 밤별 확률 3일 1/50, 4일 1/25, 5일 1/10 (2일 1/1000, 1일 0). 한 밤 CCTV ~40번이면 그날 만날 확률 약 55% / 80% / 98%.
  - 처음엔 "하룻밤 한 번 굴림"이었는데 그러면 5일차에도 열에 아홉은 안 나와서 바꿈.
- **몰래 자리잡기:** 주사위 성공 → **카메라가 모니터 앞에 다 들어감(`CCTVController.isFullyIn`) + 준영 자리가 플레이어 화면 밖(화면 범위 판정)**일 때만 나타남. → 생기는 순간이 절대 안 보임. (CCTV 화면에서도 창문 왼편이 살짝 보여서 "다 들어감"만으론 부족했음) "화면에 보이나"는 시야 범위 + **가려짐(카메라→몸 지점 Raycast)**까지 봄 — 범위만 보면 FOV가 넓어서 모니터 뒤에 가려져도 '보임'이 됐음. 조건이 한 번도 안 맞고 내리면 그 주사위는 무효.
- **드러남:** CCTV 내리면 원래부터 서 있던 것처럼 → **유예 5초.**
- **피함:** 유예 안에 CCTV를 **다 들어갈 때까지** 올림 → 사라짐(역시 화면 밖일 때만) → **20~30초** 쉼(주사위 안 굴림). CCTV 올린 동안은 유예 멈춤. 다 들어가기 전에 내리면 피한 게 아님.
- **armed:** 유예 중 정면에서 다른 구역으로 돌림(또는 다른 구역에 있는 채로 유예 끝). **armed로 정면 복귀 → 점프스케어.** 정면 보는 채로 유예 끝나도 점프스케어.
- **결과:** 점프스케어 + 환기 오류 → **그날 퇴장**(하루 1회).

  - 원작도 개별은 동시에 못 하고, Reboot All은 한꺼번에 하는 대신 오래 걸림(그래도 하나씩 하는 것보다 빠름 — 우리 5초×3 = 15초 > 8초).

## 15.19 현우 관리실 환풍구 = 불빛에만 보임 + "등 뒤로" 갑툭튀 (구현, 2026-11-26 — 유저 설계)
- **불빛에만 보임 (FNAF1 문 불빛식):** 관리실 환풍구에 있는 귀신은 불빛 버튼을 누르고 있을 때만 보임, 평소엔 암흑. `VentLightReveal.cs`(렌더러만 끔). 지금은 현우, **나중에 현승 R3(환풍구 루트)에도 그대로 붙이면 됨.**
- **나타나고 사라지는 순간이 안 보이게:**
  - 도착: 플레이어가 환풍구를 볼 수 있을 때(불빛 켜짐 + 셔터 열림)는 미룸 → **끄는 순간 도착**. 계속 켜두면 미뤄질 뿐 막히진 않음(손 한 번 떼면 바로 들어옴). 켜두는 대가 = 환풍구 구역에 묶임 + 연호 방치 흉포(20초).
  - 격퇴: 셔터 뒤라 원래 안 보임. 5시 퇴장도 불빛으로 보고 있으면 끌 때까지 기다림.
  - 등 뒤로: 화면 전환은 환풍구 구역에선 못 하니 자연히 안 보임(환기 오류 강제 전환은 가장 어두운 순간).
- **판정 후 흐름 (유저 설계):**
  1. 셔터 판정 시간 지남 → armed: **아직 환풍구에 있음**(셔터 닫아도 소용없음, 이때 고개 돌려도 안 당함).
  2. **화면 전환** 또는 **`comeBehindTime` 6초**(옛 armedGrace — 불빛 계속 켜두는 사람 대비) → **등 뒤로 옴 = 환풍구에서 사라짐**(격퇴랑 똑같이 보임 = 심리전). 불빛 켜고 노려보던 중이면 눈앞에서 사라지는 게 보임 — 계속 켜둔 대가.
  3. 등 뒤에 있을 때 **환풍구 말고 다른 구역으로 시야를 돌리는 순간 갑툭튀**(스택+1). 환풍구 쪽으로 돌리는 건 안전 → 빈 환풍구 보고 "사라졌네?" → 다른 데로 돌리면 뒤에서 튀어나옴.
  - `behindAttackTime`(기본 0 = 끔): 등 뒤에 온 뒤 고개를 안 돌려도 N초 뒤 갑툭튀. 유저 설계는 "고개 돌릴 때만"이라 꺼둠. 가운데 구역에서만 버티는 플레이(CCTV·창문·종 다 가운데)가 보이면 켜기.
  - 옛 `armedRecognizeDelay`(armed 후 1초 뒤부터 시야 이탈 감지)는 없앰 — 이제 등 뒤로 와야만 당하니 필요 없음.
- **불빛 배터리 소모: 안 함**(유저 결정 — 너무 힘듦).
- **구멍 수정:** 불빛 버튼 누른 채 고개를 돌리면 다른 구역에서도 불빛이 켜진 채 남을 수 있었음 → 환풍구 구역을 벗어나면 불빛 자동으로 꺼짐(`ShutterController.Update` 한 줄). 그래서 "불빛 켜짐 = 환풍구를 보고 있음"이 항상 성립.
- **버그 수정 (유저 발견):** 현우가 관리실 환풍구에 도착해도 판정이 한참 뒤에 시작됐음 — 도착 후 주사위(씬 `cycleTime` 11초, rand < AI)를 한 번 더 통과해야 판정이 시작되는 구조였음(3일차 AI 6이면 평균 약 37초). 그동안 셔터를 닫아도 격퇴가 안 되고 배터리·공기 게이지만 낭비. → **도착 즉시 판정 시작**으로.
- **화장실 → 관리실 환풍구 이동에도 CCTV 지직**(유저 요청). 화장실 CAM 보다가 지직 + 사라짐 = "환풍구로 갔다" 단서.
- **허공 대기 밤별 배율 `voidWaitScaleByNight` {0, 1, 1, 0.7, 0.45, 0.3}**(유저: "초반엔 별로 안 나오고 후반엔 많이 와야 스릴"). 씬 `fixedNodeWaits[0]` 101~164초(유저 조정)를 기준(배율 1)으로 → 3일 약 71~115초 / 4일 약 45~74초 / 5일 약 30~49초. 숫자는 플레이하며 조정.
- **셔터 가림 보장:** 씬 위치상 카메라→현우(`HW_VEnt`) 시선이 닫힌 셔터 중심에서 약 0.7m 비껴가서, 셔터 크기에 따라 닫아도 옆으로 보일 수 있었음 → `ShutterController.IsCoveringVent`(닫힘 + 90% 이상 내려옴)일 땐 불빛 켜도 안 보이게.
- **나중에 챙길 것:** 5시 퇴장은 판정 중이면 판정 끝나고 나가서, **5시 이후에 3스택 배선 고장이 날 수 있음.** 지금은 20초 자동 복구라 문제없지만, 창고런 만들 때 기획서의 "5시 이후 창고런 없음"과 맞춰야 함(예: 5시 이후엔 배선 고장 대신 배터리).
- **1스택 "잠깐 시야 흐림" 뺌**(유저, 플레이 후 — 환기 오류 흐려짐이랑 똑같아 보여서). 1스택 = 조명 가끔 깜빡만.
- **관리실이 조명 꺼져도 너무 밝음(유저 발견):** 원인 = `Directional Light`가 그림자 없음(Shadows: None)이라 벽·천장을 뚫고 관리실 안까지 비춤. 지울 필요는 없음(CCTV 방들·창문 밖이 이걸로 밝음). → 그림자 켜서 벽이 막게 하는 걸 먼저 시도. 제대로 된 밤 조명은 Phase 8.

  - **유저가 적용한 값:** `Directional Light` 밝기 0.24 + 살짝 파란색 + 그림자 Soft / 관리실 진짜 조명 `Lights/Real Light`(Point, Realtime, 그림자 켬)를 `RoomLights`에 연결 → 임시 천장등 안 생김 / `Siren`은 오브젝트는 켜고 Light 컴포넌트만 꺼둠(VentAlarm이 켜고 끔 — 오브젝트를 끄면 경고등이 아예 안 나옴).

## 15.20 CCTV UI = 모니터에 붙은 World 캔버스 (구현, 2026-11-26)
- **바꾼 것:** CCTV 방 버튼·종 버튼(`CCTV Swtichs`)을 화면 Overlay → **모니터 World 캔버스 `CCTVWorldCanvas`**(기존 배터리용 `WorldCanvas`를 이름 바꿔 재활용, `CCTV_Screen` 자식). 레이어 **PanelUI** → 패널처럼 고해상도 글자 카메라(`PanelUI_Camera`)가 그림. 배터리 글자(`BatteyLeft`)도 같은 캔버스, PanelUI 레이어. `MonitorDisplay.buttonGroup`은 옮기기만 해서 연결 그대로.
- **클릭이 안 됐던 원인 2개 (겪은 것):**
  1. Event Camera를 `PanelUI_Camera`로 넣음 → 이 카메라는 RT(1600×1200)에 그려서 마우스 위치를 RT 픽셀 기준으로 계산 → 클릭 지점 어긋남 + 화면 오른쪽은 "화면 밖" 처리. **World 캔버스 Event Camera는 항상 `UIRayCamera`**(화면 기준, RT 비율 맞춤).
  2. `UIRayCamera` Near 0.3 → 캔버스가 모니터 앞면보다 1.75cm 앞이라 CCTV 볼 때 카메라에서 **29.5cm** → Unity 클릭 판정(`GraphicRaycaster` IgnoreReversedGraphics)이 Near보다 가까운 버튼을 "뒤집힌 버튼"으로 보고 무시. → **`UIRayCamera`·`PanelUI_Camera` Near 0.1**(둘 다 렌더링·클릭 전용이라 다른 데 영향 없음).
- **글자 깨짐 원인:** ① 가로로 눌린 크기 — `CCTV_Screen`이 늘린 큐브(0.036×0.42×0.50)라 그 자식 캔버스는 가로:세로가 1.2:1이고, `CCTV Swtichs` Scale X 0.51까지 곱해져 글자가 가로 53%로 눌림. **TMP는 글자 테두리 선명도를 세로 크기로만 계산**해서 눌린 글자는 세로획이 깨짐. ② `PanelUIRT`(실제 1600×1200 — 예전 문서의 1440×1080은 틀림)가 Filter Mode **Point**라 화면 크기로 늘리고 줄일 때 픽셀 줄이 빠지거나 겹침. → 보정값(그룹 Scale X 0.956 + 버튼 너비·위치 보정, 배터리 Scale X 0.84, RT Bilinear)을 안내했고, 유저는 버튼 크기·배치를 직접 조정한 뒤 "글자 괜찮다"로 확인.
  - ⚠️ `CCTV_Screen` 크기를 바꾸면 그 자식 캔버스 비율이 다시 틀어짐. 글자가 다시 깨지면 이 원인부터 볼 것.
- **UI 이미지로 바꾸기 (나중):** 각 버튼의 `Image` 칸에 스프라이트(Texture Type = Sprite (2D and UI))만 넣으면 됨. 클릭은 Button + Image의 Raycast Target이 그대로 하고, 글자(TMP)는 지우거나 남겨도 됨. 반투명 PNG 가장자리도 `RawImageHIgh`의 `UI/PremultipliedRaw` 셰이더가 제대로 섞음(일반 UI 이미지도 RT에 premultiplied로 그려짐). 새 버튼을 만들면 레이어 PanelUI 확인.

## 15.21 환풍구 자리 관리 (VentOccupancy) + 현승 R3 환풍구 루트 (구현, 2026-11-26)
- **현승 STRIKE1 캐스케이드 = 완료 처리(유저 확인).** 기획서 ✅ 확정본 "잔상식 — 따로 잠그지 않음"이 현행 = 지금 코드(잔상 1.5초 + 오디오 고장 → 연호 흉포 + CCTV 강제 다운이 화면 전환이 돼서 연호가 틈탐). 행동상세 §1.4의 "~10초 CCTV/패널 잠금"은 옛 내용.
- **R3 (기획서 §2 "환풍구 변칙"):** 3밤부터 루트 고를 때 `r3ChanceByNight` {0,0,0,0.15,0.15,0.15} 주사위 → 성공하면 R3, 실패하면 나머지 루트 중 랜덤(유저 확인). 노드 = [허공, 착석, 기립, 공부방2, 환풍구(CAM), 화장실, **관리실 환풍구**] — 현우 환풍구 노드 재활용. 테스트 `testR3ChanceOverride`(0~1, -1 = 끔).
- **R3에서 못 막으면 = A안(유저 결정):** 현우처럼 셔터 판정 A(`ventInfiltrationLimit` 15 / `ventHoldRequired` 5 / `ventEarlyLeaveChance` 0.1 — 현승 쪽에 따로, 나중에 다르게 조절 가능). 격퇴 → 처음으로(루트 다시 뽑음). 침투 → **창문과 같은 armed**(화면 전환 즉시 또는 `armedAutoDelay` 5초 → STRIKE1). 관리실 환풍구에선 **불빛에만 보임**(`VentLightReveal` 자동으로 붙음), 불빛으로 보고 있으면 **끄는 순간 도착**(현우와 같음).
  - 불빛으로 누가 왔는지 확인할 이유가 생김: 현우는 환풍구를 계속 보고 있으면 당하는 걸 미룰 수 있고(등 뒤로), 현승은 화면 전환이나 5초면 무조건 STRIKE1.
- **환풍구 자리 관리 `VentOccupancy.cs` (유저 제안 "isVentUsing" — 한 명씩 오게, 우선순위 있게):**
  1. **한 번에 한 귀신.** `IsVentUsing`. 쓰는 중 = **들어오기로 한 순간**(불빛 꺼지길 기다리는 시간 포함)부터 **사건 끝**(격퇴 / STRIKE1 / 갑툭튀 / 퇴장)까지. 현우 **"등 뒤로"도 쓰는 중** — 환풍구는 비어 보여도 사건이 안 끝남 → 현우 등 뒤 + 현승 환풍구 이중 처벌 없음.
  2. **막혔을 때 귀신마다 다르게:** 현우 = 환풍구밖에 길이 없어서 **화장실(사각)에서 대기** / 현승 = **기다리지 않고 창문으로 돌아감**(지금 노드를 R1에서 찾아 R1 뒷부분으로 갈아탐: 화장실 → 세로복도 → 창문). ⚠️ 그래서 R3의 화장실 노드는 **R1과 같은 `Hs_Bathroom_Inside`**여야 함 — R1에 없으면 돌아갈 길이 없어서 그 굴림은 제자리.

- **이동:** 엔진A 그대로(흉포 포함). 전진 = 창문에 더 가까운 옆방 / 후퇴 = 더 먼 옆방 → 같은 거리 옆방 → 멈춤(막다른 방).

## 15.25 연호 창문앞 = 복도 조명 깜빡 + 실루엣 (구현, 2026-11-27 — 유저 요청)
- **유저:** "여노가 창문앞일 때 창문앞 조명이 깜빡깜빡 하게" + "원래 여노가 앞에 왔을 때는 실루엣만 보이게 하기로 했잖아"(기획서 "창문 = 육안(실루엣) 확인").
- **언제:** 연호가 창문 쪽에 있는 동안 = 창문앞 · 빼꼼 · 종에 반응해 떠나는 중(반응 텀). 떠나면(종에 끌려감 / 비상 종 / 관리실 안 / 6시 / 방전 암전으로 꺼짐) 바로 원래대로. **관리실 안으로 들어가면 조명이 멀쩡해짐**("간 줄 알았는데" — 어차피 올리고 있는 중이라 못 봄).
- **`WindowCorridorLight.cs`(신규):** 창문앞 복도 조명. 평소 켜짐(`normallyOn`), 연호가 창문 쪽이면 불규칙 깜빡(켜짐 0.04~0.25초 / 꺼짐 0.05~0.45초, 15% 확률로 0.6~1.3초 길게 꺼짐). **켜고 끄기(enabled)만.** `lights` 비우면 임시 포인트 조명을 창문앞 연호 뒤 복도 쪽(플레이어→연호 방향 0.6m, 위 1.3m)에 자동 생성 — 역광. 씬에 없으면 연호가 자동 생성(`GetOrCreate`). 관리실 조명(RoomLights)·환풍구 불빛·Siren과 별개, **배선 고장·방전 암전과는 아직 안 엮음**(방전 연출은 Phase 8에서 다시 — 지금은 암전 중에도 복도 조명은 평소대로).
- **`Silhouette.cs`(신규, 재사용 가능):** 모델 아래 모든 렌더러 재질을 검은 무광(URP Unlit)으로 바꿨다가 되돌림. 재질 칸 비면 자동 생성(`CCTV_ShadingMat`이 URP Unlit이라 빌드에도 셰이더 포함). 연호 모델에 연호가 자동으로 붙임. 현승 등 다른 귀신에도 붙여 쓸 수 있음.
- 깜빡 꺼진 순간엔 검은 실루엣도 어둠에 묻힘 → 번쩍일 때만 모양이 보임. CCTV 보는 중엔 창문이 안 보이니 숨소리만.
- **같이 본 플레이 로그(11-27 3일차 3판):** 세 판 다 연호에게 일찍 죽음 → 다른 귀신을 볼 시간이 적었음(현승 창문 1번, 현우 0~1번, 김욱 3번, 준영 0번). 마지막 판: 현승 응시하는 사이 연호 창문앞 → 빼꼼 → 빼꼼에서 비상 종(헛방 — A안 규칙) → CCTV 올려 공부방2에 종(헛방 — 세로복도에 쳐야 함) → 2.5초 지나 관리실 안 → 내리자 즉사.
- **조명 연결 수정 (유저 발견):** 연호 Inspector의 `Window Light` 칸이 스크립트(`WindowCorridorLight`) 타입이라, 유저가 만든 `Lights/Window Corridor Light`(그냥 Light)가 안 들어갔음 — 빈 칸에 "None (Window Corridor Light)"로 떠서 헷갈림. → 연호에 **`Corridor Lights`(Light 배열) 칸**으로 바꿈. 깜빡임 담당 스크립트는 계속 자동 생성되고 이 칸의 조명을 받아 씀(`UseLights`). 조명 고르는 순서: 연호 칸 → 스크립트 lights 칸 → 스크립트를 붙인 오브젝트의 Light → 임시 조명.
- **유저 결정 (11-27, 플레이 로그 본 뒤):** ① 현승은 실루엣 안 함 — 그래픽 때 창문앞을 어두컴컴하게 할 거라 상관없음. ② 빼꼼 규칙 그대로(빼꼼에서 비상 종 헛방, 2.5초 유지). ③ 다음 작업 = **창고런**(윤진 환풍구 몬스터 아이디어는 보류 — 소리로만 알고 불빛 켜면 덮치는 안 정도로 얘기만 함). ④ CCTV 문 연결선(임시 UI) 제안은 설명 다시 하기로.
